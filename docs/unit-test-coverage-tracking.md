# 单元测试覆盖率追踪

最后更新：2026-09-03

## 目标

使 `components/` 下生产代码的行覆盖率和分支覆盖率均达到 100%。

## 统计口径

使用与 CI 相同的采集配置：

```bash
dotnet test tests/AntDesign.Tests/AntDesign.Tests.csproj \
  -f net8 \
  --no-build \
  --collect:"XPlat Code Coverage" \
  --settings tests/coverage.runsettings \
  --results-directory coverage/dotnet/<iteration>
```

文档同时记录两种口径：

- **CI 原始口径**：Cobertura 根节点数据，与 Codecov 输入一致，目前包含 `obj/` 下的生成代码。
- **可行动口径**：按源文件路径去重并排除 `obj/`，用于选择下一轮测试目标。

分支数来自 Cobertura 的 `condition-coverage`；分支缺口为“有效分支数 - 已覆盖分支数”。

## 下一步队列

优先处理未覆盖行数高的区域，其次处理分支覆盖率低的区域：

1. `table`：选择、筛选、列渲染、查询序列化、固定行与展开行。
2. `select`：标签/多选模式、筛选、数据源变化、键盘与浮层生命周期。
3. `date-picker`：范围、键盘、禁用日期、预设、模板与解析。
4. `modal`：服务/确认路径、对话框生命周期、拖拽/缩放/最大化与释放。
5. `tree`、`form`、`tabs`、`menu`。
6. Core：依次处理 `Helpers`、`Component`、`Forms`、`Internal`、`JsInterop`。
7. 零覆盖区域：`calendar`、`config-provider`、`image`，以及 Core 的 `Internal`、`HashCodes`、`DynamicComponent`。

## 每轮执行步骤

每轮必须按以下步骤执行：

1. 生成一次成功的全量覆盖报告；测试失败时不得更新覆盖率数据。
2. 选择目标时排除 `obj/`，但保留 CI 原始总数用于和 Codecov 对比。
3. 选择互相独立的源码区域并行补测试，避免多个任务修改同一文件。
4. 写测试前先从 Cobertura 提取未覆盖行和分支条件。
5. 优先通过公共 API 编写行为测试；仅在基础设施没有可访问入口时使用反射。
6. bUnit JS 互操作必须使用 `SetResult` 或 `SetVoidResult` 完成；悬空计划会导致测试宿主挂起。
7. 第一次修改后立即运行对应测试类的窄测试。
8. 将本轮新增测试一起运行，检查共享状态和时序问题。
9. 运行带覆盖率的完整 net8 测试套件。
10. 更新本文档的汇总、两张明细表、迭代历史、累计增量和下一步队列。

## 完成标准

仅当一次成功的全量运行同时满足以下条件时，才算达到目标：

- CI 原始行覆盖率为 100%。
- CI 原始分支覆盖率为 100%。
- 组件和 Core 可行动表中，未覆盖行与未覆盖分支均为 0。
- 除 `obj/` 生成文件外，不排除任何生产代码路径。
