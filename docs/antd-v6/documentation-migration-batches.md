# Documentation migration batches

The documentation migration is complete when the three hosting models render the
same documentation features with Ant Design v6 component styles, all Dumi-owned
layout rules are represented by Blazor markup and `CssInJs.CreateStyles` objects,
and the old compiled documentation stylesheet is no longer loaded. Verification
must include builds and browser checks for the home page, component page, theme
preview, Semantic DOM preview, responsive navigation, and theme modes.

| Batch | Scope | Acceptance | Status |
| --- | --- | --- | --- |
| 1. Style ownership and startup | Load the v6 theme stylesheet synchronously in all hosts; have the theme switch update that same link. | Exactly one active Ant Design v6 theme link; no late default-theme flash or duplicate theme links. | In progress |
| 2. Shared shell | Header, navigation, search, language/version controls, footer, responsive and RTL states. | Shell rules come from style objects and generated classes; no legacy shell rules remain in `docs-layout.css`. | In progress |
| 3. Documentation content | Markdown typography, TOC, previous/next navigation, API tables, code boxes and demos. | Representative English/Chinese component docs match expected layout at desktop/mobile widths. | In progress |
| 4. Home and previews | Home sections, theme preview, Semantic DOM preview, theme controls and Happy Work effect. | Previews and home styles are component-scoped; no inline style or global highlight leakage. | In progress |
| 5. Legacy CSS retirement | Separate and remove Ant Design v4 reset/tokens/component rules; remove `docs-layout.css` and obsolete Less build remnants. | No old compiled document CSS/LESS is loaded or required. | Pending |
| 6. Cross-host regression | Validate Wasm, Server and WebApp plus light/dark/compact combinations and mobile/RTL. | All host builds pass and browser smoke checks pass; migration inventory is fully checked off. | Pending |

## Browser comparison checkpoint (2026-09-23)

- Started the WebApp host on `http://127.0.0.1:8182` and the React Dumi
  reference host on `http://localhost:8000`.
- Browser smoke checks now render the Blazor home page, component overview,
  Button page, and Semantic DOM Preview. The header version renders `6.6.4`,
  and the Semantic DOM preview renders the expected `v6.0.0` labels without
  Razor interpolation text leaking into the DOM.
- The browser comparison found that React injects runtime CSS-in-JS rules
  (roughly 960 style tags on the home page), while Blazor loads the v6 theme
  link plus the remaining documentation shell stylesheets. This is an
  implementation difference, not yet a visual-equivalence result.
- The comparison also found real catalog differences: React v6 exposes newer
  entries such as App, ColorPicker, Listy, QRCode, and Splitter. The Blazor
  metadata now exposes App, ColorPicker, Listy, QRCode, and Splitter in the
  matching categories; the remaining catalog difference is tracked below.
- The remaining browser gate is therefore still open: retire
  `docs-layout.css`/`dumi-docs.css` dependencies where their rules have not
  been migrated, then compare representative component HTML and computed CSS
  for every supported page.

## Browser comparison checkpoint: v6 Button token scope

- Updated `Button` to emit the React v6 class contract: legacy type aliases
  plus `ant-btn-color-*` and `ant-btn-variant-*`. Parameter updates now rebuild
  the class map, so changing `Type` after first render is reflected in the DOM.
- The compiled React stylesheet is normalized at the generator boundary: its
  internal `css-var-_R_*_` selectors are translated to the stable
  `.ant-theme` ancestor contract. `ClassMapper` no longer emits a React
  renderer identifier, and ConfigProvider supplies the stable theme scope;
  this keeps component token values independent of compile-time/random React
  class names. ConfigProvider also skips unset generated token values and
  preserves valid v6 stylesheet variables; token kebab casing keeps
  `LG/SM/XXS` groups together.
- Removed the old homepage Banner button overrides and changed the hero
  buttons to v6 large buttons. Browser comparison now reports the primary
  hero button as 40px high, 8px radius, 15px horizontal padding, and the
  React homepage's `#1668dc` color and `0 2px 0 rgba(23,117,249,0.31)` shadow;
  the GitHub button is an outlined default button with the same v6 geometry.
- Automated browser scan: 72 component routes, 210 buttons across 70 pages,
  and 35 docs/chart routes with 105 buttons; unresolved scope, zero-height,
  transparent-solid and borderless-outlined anomalies: 0.
- Current migration totals: CSS components 72/72; themes 13/13; standard
  algorithms 0/3; Semantic DOM component catalog 59/59; React Semantic DOM
